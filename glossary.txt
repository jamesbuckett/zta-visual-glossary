Alpaca — Local HTTP Proxy for Command-Line Tools
    A proxy you run on your own machine so curl, git, and npm can get out through the corporate one — it reads the PAC file and answers the NTLM or Kerberos challenge that command-line tools cannot.
    [Network Technology, Security Technology] · aka samuong/alpaca, local HTTP proxy, NTLM proxy, proxy authentication, 407 Proxy Authentication Required, Proxy-Authenticate, Negotiate, SPNEGO, http_proxy, https_proxy, corporate proxy, NTLM_CREDENTIALS, ALPACA_PROXY_AUTH_ALLOWLIST, localhost:3128
    1. Tools know one proxy — curl, git, npm, pip and docker mostly understand one thing: an http_proxy variable naming a single host and port. Alpaca is that host and port, on loopback.
    2. The PAC picks a route — For each request Alpaca evaluates FindProxyForURL from the PAC file to decide DIRECT or which upstream proxy to use.
    3. A CONNECT tunnel — For HTTPS it opens a CONNECT tunnel, so it sees only the host and port.
    4. It answers the 407 — When the upstream answers 407 it parses the Proxy-Authenticate header and runs the handshake itself: Negotiate, then NTLM, then Basic.
    5. Any process can use it — The listener has no authentication of its own, so any process that can reach that loopback port borrows your authenticated egress.
    Key fact: Alpaca is an honest compatibility shim for the perimeter model rather than a zero-trust component.

BGP — Border Gateway Protocol
    The routing protocol that stitches the internet's networks together.
    [Protocol, Network Technology] · aka autonomous system, peering
    1. Advertise a range — An autonomous system, a large and independently run network, advertises which IP ranges it can reach.
    2. Pass it on — Neighbouring autonomous systems advertise the range onward, so AS D hears of it along more than one path.
    3. Choose by policy — AS D chooses a path by policy rather than purely shortest-path, reflecting commercial peering and transit relationships.
    4. One misconfiguration — A single misconfiguration can reroute or black-hole traffic globally.
    Key fact: BGP is what makes the internet a network of networks.

Calico — Project Calico — Kubernetes Networking & Network Policy
    The Kubernetes CNI that routes pod traffic with BGP instead of tunnelling it, and layers an ordered, tiered policy engine over what Kubernetes NetworkPolicy can express.
    [Network Technology, Security Technology] · aka Project Calico, CNI, Container Network Interface, calico-node, Felix, Typha, BIRD, confd, calicoctl, GlobalNetworkPolicy, HostEndpoint, policy tiers, IPIP, VXLAN, IPAM, BGP peering, eBPF data plane, default deny, Tigera
    1. Each node owns a block — Each node owns a block of the pod address space, and a BGP daemon on that node advertises the block to the other nodes or to the physical fabric.
    2. Route, don't tunnel — A pod's packet crosses the wire carrying the pod's own source and destination address with nothing wrapped around it. Where the underlay will not carry pod routes, Calico falls back to a VXLAN or IP-in-IP overlay.
    3. Felix programs the kernel — A Felix agent on every node inserts routes into the kernel and access control rules into the chosen data plane: iptables, nftables, eBPF or Windows HNS.
    4. Tiers, in order — Every policy lives in a tier, tiers are evaluated by order, and a tier can Pass a packet down to the next. A platform team writes global rules in a high-precedence tier.
    5. Developers can't override — Developers' Kubernetes NetworkPolicies land in the default tier, fixed at order 1,000,000, where they cannot override what sits above. RBAC per tier enforces the boundary.
    Key fact: Calico resolves label selectors into IP sets, so a policy is only as trustworthy as the labels and the IPAM behind it.

Cilium — eBPF-Based Kubernetes Networking, Observability & Security
    The Kubernetes CNI that compiles identity-aware policy into eBPF programs in the kernel, so enforcement, load balancing, and flow visibility happen without a sidecar.
    [Network Technology, Security Technology] · aka CNI, Container Network Interface, cilium-agent, CiliumNetworkPolicy, CiliumClusterwideNetworkPolicy, security identity, kube-proxy replacement, Hubble, Cluster Mesh, Tetragon, Gateway API, Maglev, direct server return, Isovalent
    1. Labels, not addresses — Pods are created and destroyed constantly, so an IP address identifies nothing durable. Cilium stops writing policy about addresses.
    2. A numeric identity — Its control plane collapses each pod's label set into a numeric security identity and distributes that mapping cluster-wide.
    3. Identity travels — The identity is carried with the packet, so the receiving node can decide without a second lookup.
    4. Policy between identities — Policy names label selectors and holds as pods churn. Beyond layer 4 it can admit particular HTTP methods and paths, gRPC calls or DNS names, via an Envoy per node rather than a sidecar per pod.
    5. eBPF in the kernel — The same eBPF data plane replaces kube-proxy, and Hubble reads those programs to produce per-flow records annotated with identity rather than IP.
    Key fact: The identity is only as good as the labels behind it: whoever can set labels can select a policy.

Cntlm — NTLM Authentication Proxy
    The long-standing C daemon that speaks NTLM to a corporate parent proxy on your behalf — it probes to find the dialect the proxy will accept, and holds a password hash rather than a password.
    [Network Technology, Security Technology] · aka CNTLM, cntlm.conf, NTLM proxy, NTLMv2, NTLM2SR, LM hash, PassNTLMv2, PassNT, PassLM, magic dialect detection, parent proxy, gateway mode, NoProxy, SOCKS5 proxy, port tunnelling, ISA Server
    1. Tools point at loopback — Cntlm listens on 127.0.0.1:3128, forwards to a parent proxy, and adds the NTLM handshake the application behind it cannot perform.
    2. Find the dialect — The Auth setting selects the dialect, strongest to weakest: NTLMv2, NTLM2SR, NT, NTLM or LM. cntlm -M probes with the strongest hashes first and prints a working configuration.
    3. Hashes, not a password — cntlm.conf holds hashes printed by cntlm -H rather than a password. But they are exactly what the NTLM exchange consumes, so whoever can read that file can authenticate as you.
    4. Gateway mode — With -g, Cntlm listens on every interface and other machines can share it, gated only by -A and -D rules on IP and mask: authenticated egress granted by network position.
    Key fact: Cntlm is best understood as a prosthesis for a proxy you do not control rather than a design to carry forward.

CORS — Cross-Origin Resource Sharing
    A browser rule that lets a server declare which other origins may read its responses.
    [Protocol, Security Technology] · aka same-origin policy, preflight, Access-Control-Allow-Origin
    1. Script calls another site — When script on one site calls another, the browser attaches an Origin header to the request.
    2. Server allows the origin — The browser only exposes the reply if the server returns a matching Access-Control-Allow-Origin. That is how a server relaxes the same-origin policy.
    3. Preflight first — Requests that are not simple, with custom headers or methods like PUT, trigger a preflight OPTIONS check first.
    4. Browsers only — CORS is enforced only by browsers: it governs in-browser JavaScript, not server-to-server calls.
    Key fact: CORS is no substitute for real authorisation.

CSRF / XSS / CSP — Web App Attacks & Content Security Policy
    The two classic browser attacks — and the header that helps shut them down.
    [Security Technology, Protocol] · aka cross-site request forgery, cross-site scripting, content security policy, same-origin, SameSite, injection
    1. XSS injects script — Cross-Site Scripting injects attacker-controlled script into a page so it runs with the victim's session, stealing tokens or acting as the user.
    2. Escape and validate — XSS is defeated by escaping output and validating input.
    3. CSRF forges a request — Cross-Site Request Forgery tricks a logged-in user's browser into firing an unwanted state-changing request to a site where they are authenticated.
    4. Tokens and SameSite — CSRF is defended with anti-CSRF tokens and SameSite cookies.
    5. CSP limits the damage — Content Security Policy is a response header that whitelists which script, style and connection sources a page may load, sharply limiting what injected code can do even if XSS slips through.
    Key fact: None is sufficient alone: defence in depth is the point.

DHCP — Dynamic Host Configuration Protocol
    Automatically hands out IP addresses to devices joining a network.
    [Protocol, Network Technology] · aka DORA, lease
    1. Discover — A device that has just connected begins a short exchange with a DHCP server by sending a Discover.
    2. Offer — The DHCP server replies with an Offer.
    3. Request — The device answers with a Request.
    4. Acknowledge — The server confirms with an Acknowledge. The device now has its IP address, subnet mask, default gateway and DNS servers, with no manual setup.
    5. A limited lease — The server leases each address for a limited time.
    Key fact: DHCP is why a phone just works the moment it joins a new Wi-Fi network.

Django — Django (Python web framework)
    A batteries-included Python web framework for building sites fast.
    [Development Framework] · aka MTV, ORM
    1. Route the request — An incoming request is routed by its URL to a view.
    2. Pull data via models — The view pulls data through models, using the ORM (object-relational mapper) for database access.
    3. Render a template — The view renders a template. Model, template and view make up Django's MTV pattern.
    4. Return the response — The rendered template becomes the response.
    5. Out of the box — Django ships with an ORM, an auto-generated admin interface, authentication and routing out of the box.
    Key fact: Django's philosophy is to handle the plumbing so you can focus on the application.

DNS — Domain Name System
    The internet's phonebook: turns human names into IP addresses.
    [Protocol, Network Technology] · aka DNSSEC, resolver
    1. Client asks — A client needs the IP address behind a human-readable name like example.com, and asks a resolver.
    2. Root servers — The resolver walks a hierarchy from the top, starting with the root servers.
    3. Top-level domain — Next it asks the server for the top-level domain.
    4. Authoritative server — Last it reaches the authoritative server for the domain itself.
    5. Answer and cache — The resolver returns the IP address the machine will route to, and caches the answer along the way to stay fast.
    Key fact: DNS is also a powerful control point for security and filtering.

DOCA — NVIDIA DPU Software Framework
    The SDK for BlueField — 'what CUDA is to the GPU, DOCA is to the DPU' — with libraries and services to offload networking, storage, and zero-trust security.
    [Development Framework, Security Technology] · aka NVIDIA DOCA, DOCA SDK, DOCA Argus, App Shield, DOCA Flow
    1. CUDA for the DPU — DOCA is NVIDIA's software framework for programming BlueField DPUs and SuperNICs, positioned as the DPU's equivalent of CUDA for the GPU.
    2. Three layers — It is layered: hardware drivers at the base, C/C++ libraries in the middle, and production-ready containerised microservices on top.
    3. Standard interfaces — It is exposed through industry-standard interfaces such as DPDK, SPDK and Netlink rather than a closed silo, which keeps software portable across BlueField generations.
    4. Argus watches the host — DOCA Argus runs on the DPU's isolated cores and inspects the host's live memory and processes: agentless intrusion detection that host malware cannot see or switch off.
    5. Integrity and tunnels — App Shield adds process-integrity monitoring, and the IPsec/TLS gateways and crypto libraries terminate encrypted tunnels at wire speed.
    Key fact: Without DOCA a BlueField card is an uninitialised accelerator; with it, the silicon becomes running zero-trust enforcement.

DORA — Digital Operational Resilience Act
    The EU regulation that makes surviving an IT failure a supervisory matter for financial firms — and, for the first time, lets European regulators oversee the cloud providers those firms depend on.
    [Security Technology] · aka Digital Operational Resilience Act, Regulation (EU) 2022/2554, 2022/2554, operational resilience, ICT risk management, TLPT, threat-led penetration testing, TIBER-EU, register of information, CTPP, critical ICT third-party provider, Lead Overseer, ESAs
    1. Financial entity — DORA binds around twenty categories of regulated firm — banks, insurers, investment firms, trading venues — and, unusually, reaches their suppliers as well.
    2. Register of information — Each firm maintains a register of information describing every ICT service dependency and where it runs.
    3. Supervisor sees the register — The register makes each ICT dependency, and where it runs, visible to the supervisor.
    4. Critical provider designated — The European Supervisory Authorities designate Critical ICT Third-Party Providers — in practice the large cloud and core-banking platforms.
    5. Overseer reaches provider — Each is assigned a Lead Overseer able to inspect it directly and to recommend that firms stop using it. European financial regulators supervising hyperscalers had no precedent.

DPU — Data Processing Unit
    A programmable processor on the network card that offloads networking, storage, and security from the host — and runs them in its own isolated trust domain.
    [Network Technology, Security Technology] · aka data processing unit, SmartNIC, infrastructure processor, IPU, infrastructure processing unit
    1. Traffic hits DPU first — The DPU fuses a high-speed network interface with its own processor, so traffic passes through it before it ever reaches the host.
    2. Own cores, own OS — Its general-purpose CPU cores, typically Arm, run their own operating system in a domain the host cannot see or control.
    3. Security on the card — Security policy executes out-of-band on the card: microsegmentation, line-rate encryption, intrusion detection and the keys all live on the DPU.
    4. Host compromised, policy holds — An attacker who takes over the host cannot reach the enforcement they would want to disable, because it sits on a separate processor.
    Key fact: Even if the host OS is completely compromised, the enforcement on the DPU stays intact.

eBPF — extended Berkeley Packet Filter
    Sandboxed programs that run inside the Linux kernel at defined hook points, extending what it does without patching it or loading a module.
    [Network Technology, Development Framework] · aka BPF, bpf(), verifier, JIT, eBPF maps, XDP, kprobe, uprobe, tracepoint, BPF LSM, libbpf, CO-RE, BTF, bpftrace, kernel
    1. Load via bpf() — You compile a small program to a bytecode and hand it to the kernel through the bpf() system call.
    2. The verifier checks — Before it is accepted, the program is statically analysed across every execution path to prove that it terminates and never steps outside its bounds.
    3. JIT to native code — Only then is it JIT-compiled to native instructions, so it runs at roughly the speed of compiled kernel code.
    4. Attach at a hook — The kernel runs it at a defined hook: a packet at the driver (XDP), traffic control, a kprobe, a tracepoint, a socket operation or a security hook (BPF LSM).
    5. Maps share state — Programs hold no state of their own. Maps, readable and writable from both the program and a user-space agent, carry counters, policy tables and event streams across the boundary.
    Key fact: The verifier proves memory safety and termination, not benignity.

EDR / XDR — Endpoint / Extended Detection & Response

Envoy — Envoy Proxy — L7 Proxy & Universal Data Plane
    The C++ L7 proxy underneath most modern meshes and gateways — a filter chain whose entire configuration arrives over a live gRPC stream rather than a file, which is what makes a control plane above it possible.
    [Network Technology, Security Technology] · aka Envoy Proxy, xDS, LDS, RDS, CDS, EDS, SDS, listener, cluster, filter chain, HTTP connection manager, ext_authz, external authorization, JWT authn filter, RBAC filter, WASM filter, Envoy Gateway, sidecar proxy, upstream, downstream, circuit breaking, outlier detection
    1. A listener — A downstream client connects to a listener, a named socket. Envoy runs out of process next to every workload rather than as a library.
    2. Filter chains — The connection passes through L3/L4 network filters, and for HTTP a second, L7 chain. There Envoy terminates mTLS, validates JWTs, matches RBAC and calls ext_authz for a per-request allow or deny.
    3. Router to cluster — The router selects a cluster, a group of logically similar upstream hosts, where a load-balancing policy picks an endpoint.
    4. Config over xDS — A management server streams configuration over gRPC (LDS, RDS, CDS, EDS, SDS), so routes, upstreams and certificates change under live traffic without a restart.
    5. Guard the control plane — Whoever can push xDS to the fleet can silently reroute traffic, swap a certificate or disable an authorisation filter across every proxy at once.
    Key fact: For zero trust, Envoy is the textbook Policy Enforcement Point, because the filter chain is exactly where enforcement belongs.

gRPC — gRPC Remote Procedure Call
    A fast, contract-first RPC framework using Protocol Buffers over HTTP/2.
    [Protocol, Development Framework] · aka protobuf, Protocol Buffers, RPC
    1. One .proto contract — The contract between services is defined in a .proto file.
    2. Generate the code — Client and server code is generated from that one contract.
    3. Call like a function — Services call one another as if invoking local functions.
    4. Binary over HTTP/2 — Data is serialised with compact binary Protocol Buffers and rides HTTP/2, enabling multiplexing and streaming with low latency.
    Key fact: gRPC is a common choice for internal microservice communication where REST and JSON prove too chatty.

HTTP / HTTPS — HyperText Transfer Protocol (Secure)
    The request/response protocol of the web; HTTPS is HTTP wrapped in TLS.
    [Protocol] · aka HTTP, HTTPS, HTTP/2, web
    1. Client requests — A browser or API client asks for a resource, using a method such as GET or POST.
    2. Server responds — The server answers the request with the resource.
    3. Stateless — Each request stands alone. Cookies or tokens carry context from one request to the next.
    4. HTTPS wraps it in TLS — HTTPS is the very same protocol running inside a TLS-encrypted channel, so the traffic is private and tamper-evident.
    Key fact: HTTPS is now the default transport for nearly all web traffic.

IPsec — Internet Protocol Security
    Encrypts and authenticates IP traffic at the network layer.
    [Protocol, Security Technology] · aka IKE, ESP, tunnel mode
    1. Transport mode — IPsec secures traffic at the IP layer, so any application's packets are protected with no changes to the application. Transport mode protects the payload, host to host.
    2. Tunnel mode — Tunnel mode wraps the whole packet, encrypting and integrity-protecting it inside a new one.
    3. Gateway to gateway — Tunnel mode between gateways is the basis of many site-to-site VPNs.
    4. IKE negotiates — Key exchange and negotiation are handled by the IKE protocol.
    Key fact: IPsec protects any application's packets with no changes to the application.

KEDA — Kubernetes Event-driven Autoscaling
    Scales Kubernetes workloads on the event source itself — queue depth, consumer lag, a Prometheus query — and all the way down to zero, which CPU-based autoscaling cannot do.
    [Development Framework] · aka Kubernetes Event-driven Autoscaling, ScaledObject, ScaledJob, TriggerAuthentication, scale to zero, scaler, external metrics, HPA, Horizontal Pod Autoscaler, consumer lag
    1. The wrong signal — A worker blocked on a queue read burns almost no CPU while messages pile up, so an HPA scaling on CPU and memory sees an idle deployment and does nothing.
    2. Declare triggers — You write a ScaledObject pointing at an existing Deployment and declare triggers, such as Kafka consumer lag or SQS queue depth. The operator watches ScaledObjects.
    3. Zero to one — KEDA drives the zero-to-one transition itself, waking an idle workload when the first event lands and returning it to zero after a cooldown.
    4. One to many — A metrics API server publishes each scaler's reading through the external metrics API, and from one replica upward an ordinary HPA does the scaling.
    5. A credential per poll — Every scaler must authenticate to whatever it polls. TriggerAuthentication keeps those credentials out of the ScaledObject; a pod identity provider means nothing long-lived is stored.
    Key fact: Scale-to-zero is the thing a plain HPA has never done.

Kerberos — Kerberos Authentication Protocol
    Ticket-based authentication that proves identity without sending passwords over the wire.
    [Protocol, Security Technology] · aka KDC, ticket-granting ticket, TGT, service principal, SPN, single sign-on
    1. Log in once — The client authenticates once to a trusted Key Distribution Center (KDC), rather than sending its password to every service it uses.
    2. Receive a TGT — In return the client receives a Ticket-Granting Ticket (TGT), a time-limited, encrypted ticket. Tickets expire quickly and rely on synchronised clocks.
    3. Swap for a ticket — To reach a service, the client presents the TGT and exchanges it for a service ticket for that one service.
    4. Present the ticket — The client presents the service ticket and the service verifies it. This ticket exchange is what makes single sign-on across a Windows domain possible.
    Key fact: The password never crosses the network.

Kubernetes — Kubernetes (K8s)
    Automates deploying, scaling, and healing containerized apps across machines.
    [Development Framework, Network Technology] · aka K8s, orchestration, pod
    1. Declare desired state — You declare the desired state: how many replicas, which images, what networking.
    2. Reconcile continuously — The control plane continuously reconciles reality to match the desired state.
    3. Schedule pods — It schedules pods, the smallest deployable unit, onto the worker nodes of the cluster.
    4. Reschedule failures — When a workload fails, the control plane reschedules it.
    5. Scale on demand — It also scales on demand, adding pods as they are needed.
    Key fact: Kubernetes turns a fleet of machines into one programmable platform.

MQTT — MQTT (historically 'MQ Telemetry Transport' — no longer an acronym)
    A lightweight publish/subscribe protocol for IoT and constrained devices.
    [Protocol] · aka pub/sub, broker, IoT
    1. Publish to a topic — Clients publish messages to named topics on a central broker.
    2. Subscribe to topics — Other clients subscribe to the topics they care about.
    3. Broker fans out — The broker passes each message to the topic's subscribers, which decouples senders from receivers.
    4. Built for weak networks — MQTT is built for low-bandwidth, high-latency or unreliable networks, with a tiny footprint and tiered quality-of-service levels.
    Key fact: MQTT's tiny footprint and tiered quality-of-service levels make it the default for sensors, telemetry and large IoT fleets.

mTLS — Mutual TLS
    TLS where both client and server prove identity with certificates.
    [Protocol, Security Technology] · aka mutual TLS, client certificate
    1. Server certificate — In ordinary TLS only the server presents a certificate.
    2. Client certificate too — Mutual TLS extends it so the client must present a certificate too.
    3. Each side verifies — Each side verifies the other before any application data flows, giving strong two-way authentication without passwords.
    4. Then data flows — Only then does application data flow, between two workloads that each carry their own cryptographic identity.
    Key fact: mTLS is a cornerstone of zero-trust service-to-service communication and of service meshes.

NAT — Network Address Translation
    Lets many private devices share one public IP address.
    [Network Technology, Protocol] · aka PAT, masquerade
    1. Private addresses — Many internal hosts each have their own private address.
    2. Rewrite IP and port — As packets cross the boundary, the NAT router rewrites their source and destination IP address and port.
    3. One public address — Many internal private addresses are mapped onto a single public one, which conserves scarce IPv4 address space and hides internal network structure.
    4. Replies find their host — The router keeps a translation table, so replies are sent back to the correct internal host.
    Key fact: NAT conserves scarce IPv4 address space and, as a side effect, hides internal network structure.

PAC File — Proxy Auto-Configuration
    A snippet of JavaScript the browser runs for every URL to decide: go direct, or through which proxy?
    [Network Technology, Security Technology] · aka proxy auto-config, FindProxyForURL, WPAD, wpad.dat, proxy.pac, automatic proxy configuration, explicit proxy
    1. Locate the file — The browser locates the PAC file from a manually configured URL, or via WPAD, which finds it through DHCP or DNS.
    2. Called per request — The browser or OS calls the file's one function, FindProxyForURL(url, host), for every request to decide how to reach it.
    3. Internal goes direct — Built-in helpers like shExpMatch(), dnsDomainIs() and isInNet() let rules match on hostname, domain or IP range, so internal traffic goes DIRECT.
    4. The rest via a gateway — Everything else is steered through a forward proxy or Secure Web Gateway for inspection and policy, with no per-application setup.
    5. WPAD can be poisoned — WPAD discovery has been repeatedly abused: a poisoned response can route all of a victim's traffic through an attacker's proxy.
    Key fact: A PAC file is the classic, agentless way to funnel web traffic through a Secure Web Gateway.

PKI — Public Key Infrastructure
    The certificate-and-trust system that lets you prove who owns a public key.
    [Security Technology] · aka certificate authority, CA, X.509, root of trust, certificate chain, ACME
    1. Trusted root — PKI binds a public key to an identity. Trust starts at a root Certificate Authority (CA) that the client already trusts.
    2. Intermediate CA — The root CA signs the intermediate CA's X.509 certificate, vouching that its key belongs to its name.
    3. Server certificate — The intermediate CA in turn signs the server's certificate, binding the server's public key to its name.
    4. Walk the chain — The client verifies each signature and walks the chain up to the root it already trusts. Every padlock in a browser is a PKI trust decision.
    Key fact: Get the root of trust wrong and everything built on it is compromised.

Post-Quantum Cryptography — Post-Quantum Cryptography (PQC)
    New algorithms designed to survive attack by a large quantum computer.
    [Security Technology] · aka PQC, ML-KEM, Kyber, ML-DSA, Dilithium, quantum-safe, harvest now decrypt later
    1. Today's public-key crypto — RSA and elliptic-curve cryptography secure today's internet, in key exchange and in signatures.
    2. Quantum breaks it — Their maths could be broken by a sufficiently large quantum computer running Shor's algorithm, undoing key exchange and signatures at a stroke.
    3. Harvest now, decrypt later — Adversaries can record encrypted traffic today and decrypt it once quantum hardware arrives, so long-lived secrets need protecting now.
    4. New standards — Post-Quantum Cryptography uses hard problems, chiefly structured lattices. In August 2024 NIST finalised FIPS 203 (ML-KEM), FIPS 204 (ML-DSA) and FIPS 205 (SLH-DSA).
    5. A hybrid rollout — PQC key exchange is being layered alongside classical algorithms in TLS, rather than replacing them overnight.
    Key fact: The urgency is harvest now, decrypt later: long-lived secrets need protecting now.

QUIC — QUIC (a name, not an acronym — RFC 9000)
    A fast, always-encrypted transport that runs over UDP and folds in the work of TCP plus TLS.
    [Protocol, Network Technology, Security Technology] · aka HTTP/3, gQUIC, RFC 9000
    1. Runs over UDP — QUIC is a transport protocol that runs over UDP and combines connection setup, TLS 1.3 encryption and multiplexed streams into one design.
    2. One round trip — The transport and cryptographic handshakes happen together, so a new connection is usually ready after a single round trip, or zero when resuming. TCP-then-TLS needs several.
    3. Independent streams — Encrypted streams are multiplexed over the one connection, independently of each other.
    4. No head-of-line blocking — One lost packet stalls only its own stream, rather than holding up everything queued behind it as it does for HTTP/2 over TCP.
    Key fact: QUIC is the foundation of HTTP/3, with encryption built in rather than bolted on.

RBAC & ABAC — Role- / Attribute-Based Access Control
    Two models for deciding who may do what — by role, or by attributes and context.
    [Security Technology] · aka role-based access control, attribute-based access control, authorization, least privilege, entitlements
    1. RBAC: user to role — Role-Based Access Control assigns people to roles, such as billing-admin or read-only-auditor.
    2. RBAC: role to permissions — Each role groups a set of permissions. That is simple to reason about, but coarse and prone to role explosion.
    3. ABAC: four attributes — Attribute-Based Access Control evaluates rules over attributes of the subject, the resource, the action and the environment.
    4. Policy engine decides — A policy engine evaluates these rules at the decision point for every request, giving a fine-grained, context-aware decision.
    Key fact: Zero Trust leans toward ABAC because trust should depend on live context, not a static role.

TCP/IP — Transmission Control Protocol / Internet Protocol
    The layered addressing-and-delivery system that moves data across the internet.
    [Protocol, Network Technology] · aka internet protocol suite, UDP
    1. Application data — Data starts at the top, in the application layer. Almost every other protocol in this glossary runs on top of TCP/IP.
    2. Transport: TCP or UDP — The transport layer adds its own header. TCP gives reliable, ordered, connection-oriented delivery; UDP is the lightweight, fire-and-forget alternative.
    3. Internet: IP — The internet layer adds the IP header. IP handles the addressing and routing of packets between hosts.
    4. Link: last header — The link layer adds the last header, wrapping everything above it. Because each layer adds only its own header, each concern is solved independently.
    Key fact: TCP/IP is the foundational suite that lets dissimilar networks interconnect.

TLS — Transport Layer Security
    Encrypts data in transit and authenticates the server you are talking to.
    [Protocol, Security Technology] · aka SSL
    1. Negotiate ciphers — A handshake opens the connection by negotiating which ciphers to use.
    2. Server's certificate — The server presents its certificate, which is how TLS authenticates the server.
    3. Agree session keys — The certificate plus public-key cryptography are used to agree on session keys.
    4. Encrypted traffic — From then on, traffic is encrypted with fast symmetric crypto, giving the connection confidentiality and integrity.
    Key fact: TLS underpins HTTPS, secure email and many VPNs.

TPM & Secure Boot — Hardware Root of Trust
    A hardware chip that protects keys and proves a machine booted clean.
    [Security Technology] · aka trusted platform module, secure boot, measured boot, attestation, UEFI
    1. Secure Boot checks — Secure Boot has the firmware verify each stage of startup against trusted signatures, refusing to run a bootloader that has been tampered with.
    2. Measured into PCRs — Measured boot records hashes of what actually loaded into the TPM's Platform Configuration Registers (PCRs).
    3. Keys stay in hardware — The TPM is a tamper-resistant chip that generates and stores cryptographic keys so they never leave the hardware.
    4. Remote attestation — A remote server can ask the TPM to attest to that record, getting cryptographic proof the device booted into a known-good state before it is trusted.
    5. A root of trust — This hardware root of trust underpins disk-encryption key release, device identity and the device-posture checks Zero Trust relies on.
    Key fact: A TPM moves the foundation of trust from software, which malware can subvert, down into silicon.

    3. No direct path — Devices on different VLANs cannot talk directly, even when plugged into the same switch.
    4. Through the router — Traffic between VLANs must pass through a router.
    Key fact: A VLAN improves security, performance and manageability without extra cabling.

VPN — Virtual Private Network

    [Network Technology, Security Technology] · aka tunnel, remote access

    2. An encrypted tunnel — It builds an encrypted tunnel so traffic crosses the untrusted internet as if it were on a private link.
    3. Into the network — At the far end the traffic reaches the private network: remote access to corporate resources, and a shield on hostile networks.
    4. The protocol decides — Underneath sits a specific protocol: IPsec, WireGuard or a TLS-based design.
    Key fact: A VPN's security and topology depend entirely on the underlying protocol.

WebSockets — WebSocket Protocol (RFC 6455)
    Upgrades an HTTP connection into a persistent, two-way channel for live data.
    [Protocol, Network Technology] · aka ws, wss, RFC 6455, Sec-WebSocket-Key
    1. Ask to upgrade — The connection starts as an HTTP/1.1 GET carrying an Upgrade: websocket header.
    2. 101 Switching Protocols — The server answers 101 Switching Protocols.
    3. Frames both ways — The same TCP socket then carries lightweight binary frames in both directions, so client and server can push messages at any time.
    4. wss:// adds TLS — Run it as wss:// to wrap the connection in TLS.
    Key fact: WebSocket removes the request/response turn-taking of plain HTTP, which is why it powers chat, collaborative editing, live dashboards and trading feeds.

WebTransport — Multiplexed streams and datagrams over HTTP/3
    A newer browser transport over HTTP/3 offering multiplexed streams and fire-and-forget datagrams.
    [Protocol, Network Technology] · aka HTTP/3 transport, datagrams, WebTransport API
    1. A session over HTTP/3 — WebTransport gives browser code a low-latency session over HTTP/3, and therefore over QUIC and UDP.
    2. Reliable streams — Within one connection it offers reliable bidirectional and unidirectional streams.
    3. Unreliable datagrams — It also offers unreliable datagrams, so an app can mix guaranteed delivery with fire-and-forget packets for things like game state or live media.
    4. No head-of-line blocking — Because it inherits QUIC's independent streams, one lost packet stalls only its own stream, avoiding the head-of-line blocking WebSockets suffer over TCP.
    Key fact: WebTransport is the emerging alternative to WebSockets, though its W3C and IETF specifications are still drafts.

WireGuard — WireGuard VPN protocol

    3. Low-overhead tunnel — The tunnel itself runs with very low overhead.
    4. Small, in the kernel — WireGuard is designed for simplicity and speed, with a codebase small enough to audit by hand, and it ships inside the Linux kernel.
    Key fact: WireGuard has rapidly become the modern default over heavier IPsec and OpenVPN stacks.
